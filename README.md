## 1. Описание продукта

Модуль предназначен для бесконфликтной координации параллельных расчётов финансовых рисков. Устраняет взаимные блокировки СУБД (Deadlocks), коллизии скользящих окон дат и затирание промежуточных данных.

### Ключевые возможности:
* **Шлюз приоритета (Люди vs Машина):** Задачи пользователей (`USER`) обладают безусловным приоритетом перед регламентным планировщиком (`MACHINE`). Фоновые задачи откладываются по таймеру (`WAITING_TIMER`).
* **Дедупликация идентичных запросов:** Перехват дублей по паре `(Process_ID + Target_Date)` без запуска лишних воркеров с автоматической подпиской пользователей на единый `run_id`.
* **Композитный Lock-менеджер:** Проверка конфликтов по ключу `(Resource_ID + Date_Range + Access_Mode)` с правилом скользящего окна ($D_{1}^{from} \le D_{2}^{to} \land D_{2}^{from} \le D_{1}^{to}$) и атомарным резервированием «всё или ничего».
* **Матрица совместимости:** Параллельное совместное чтение `READ + READ` без блокировки общих источников (`src_transactions`, `ref_clients`).
* **Изоляция вычислений:** Выборка данных в режиме `REPEATABLE READ` (MVCC), изоляция промежуточных таблиц `temp_risk_<run_id>` и финальный атомарный `MERGE` в витрину `mart_risk_results`.
* **Watchdog с Heartbeat и TTL:** Автоматическое обнаружение и снятие блокировок аварийно завершившихся воркеров по истечении TTL (25 сек) с продвижением очереди.
* **Live-дашборд и Dry-Run:** Предпроверка конфликтов до клика на кнопку «Запустить» и стриминг состояния в реальном времени через WebSocket (< 1 сек).

## 2. Быстрый запуск

### Вариант 1: Запуск одной командой через Docker Compose (Рекомендуемый для жюри)

Требуется установленный Docker и Docker Compose.

```bash
docker-compose up --build
```

После старта:
* **Веб-интерфейс дашборда:** [http://localhost:8000](http://localhost:8000) (если на Windows включён VPN/прокси, открывайте [http://127.0.0.1:8000](http://127.0.0.1:8000))
* **Интерактивная документация Swagger API:** [http://localhost:8000/docs](http://localhost:8000/docs) (или [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs))
* **WebSocket поток событий:** `ws://localhost:8000/ws/events`
* База данных PostgreSQL 16 поднимается автоматически, выполняет миграции и сидирует 50 клиентов и 1500 синтетических транзакций.

---

### Вариант 2: Локальный запуск (Desktop / pywebview или Браузер)

1. Установите зависимости:
```bash
pip install -r requirements.txt
```

2. Убедитесь, что PostgreSQL запущен и доступен по адресу `DATABASE_URL` (по умолчанию `postgresql://postgres:password@localhost:5432/risk_orchestrator`).

3. Запустите десктопное приложение или веб-сервер:
```bash
# Десктопное нативное окно (pywebview):
python desktop_app.py

# ИЛИ напрямую веб-сервер:
uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload
```

## 3. Гайд по проверке демо-сценариев для жюри

В интерфейсе дашборда ([http://localhost:8000](http://localhost:8000)) в левой панели вынесен блок **«Демо-сценарии»** для быстрой проверки критериев оценки в один клик:

| Кнопка / Сценарий | Входные параметры | Ожидаемый результат в UI |
|---|---|---|
| **1. «Запустить регламент (Cron / MACHINE)»** | Процесс от имени планировщика при наличии пользовательских задач | Задача встаёт в статус `WAITING_TIMER` (синий бейдж) в виджете таймера машины. Ожидает завершения задач людей и только затем стартует. |
| **2. «Тест дедупликации (2 аналитика подряд)»** | Одновременный запуск `credit_risk` на одну дату от «Аналитик 1» и «Аналитик 2» | Создаётся ровно **1** воркер (`RUNNING`). Второй аналитик автоматически добавляется в список `Подписчики` карточки задачи. |
| **3. «Скрытый конфликт окна (20 и 19 число)»** | `credit_risk` на 20.11 (окно 13.11–20.11, READ) и `etl_transactions` на 19.11 (окно 18.11–19.11, WRITE) | Вторая задача встаёт в блок `QUEUED` (оранжевый бейдж) с указанием конфликтующего ресурса `src_transactions` и стартует автоматически после освобождения блокировки. |
| **4. «Имитировать сбой (Chaos TTL)»** | Кнопка на любой активной карточке в блоке «Активные расчёты» | Останавливает Heartbeat воркера. Через время TTL (по умолчанию 25 с или меньше) Watchdog переводит задачу в `FAILED`, снимает локи и запускает следующую задачу из очереди. |
| **5. Живой Dry-Run** | Изменение даты или процесса в форме запуска | Индикатор под формой мгновенно пересчитывает конфликтность: зелёный (`RUN_IMMEDIATELY`), жёлтый (`QUEUE`), голубой (`DEDUPLICATE`) или фиолетовый (`WAIT_TIMER`). |

## 4. Запуск автоматических тестов

В проекте реализованы тесты согласно разделу 8 SDD:

```bash
# 1. Запуск всех тестов:
pytest -v

# 2. Функциональные тесты матрицы совместимости (TC-01 .. TC-06):
pytest tests/test_compatibility.py -v

# 3. Нагрузочный тест на 50 одновременных запросов (< 200 мс, 0% Deadlocks):
pytest tests/test_load_50.py -v
```

### Запуск тестов внутри Docker-контейнера:
```bash
docker-compose exec backend python -m pytest -v
```

```text
├── docker-compose.yml          # Спецификация сервисов PostgreSQL 16 и FastAPI backend

├── ARCHITECTURE.md             # Полный архитектурно-технический проект (SDD)
├── README.md                   # Руководство по запуску и проверке
├── pytest.ini                  # Конфигурация запуска тестов
├── config/
│   └── processes.json          # Декларативный реестр бизнес-процессов, окон дат и ресурсов
├── backend/
│   ├── main.py                 # FastAPI приложение, lifespan, подключение статики
│   ├── api/
│   │   ├── routes.py           # REST-эндпоинты (/api/runs, /dry-run, /state, /demo/*)

│   ├── core/

│   │   ├── orchestrator.py     # Главный диспетчер (asyncio.Lock, приоритеты, очередь, Watchdog)
│   │   └── worker.py           # Изолированный пайплайн воркера (MVCC, STAGING, MERGE)

│       ├── database.py         # Пул asyncpg, DDL-миграции, генератор синтетических данных

│   ├── index.html              # Разметка дашборда
│   ├── styles.css              # Стили и цветовое кодирование статусов
│   └── app.js                  # Клиентская логика, авто-реконнект WS и Live-рендеринг
└── tests/
    ├── conftest.py             # Фикстуры pytest, клиент httpx и очистка базы
    ├── test_compatibility.py   # Тесты матрицы совместимости (TC-01 .. TC-06)
    └── test_load_50.py         # Нагрузочный тест на 50 запросов (время диспетчеризации < 200 мс)
```
